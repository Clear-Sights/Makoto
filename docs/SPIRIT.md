# 誠 — the spirit of a kept word

Makoto asks a narrow question: when an agent says it did something, is that deed present in the
record the hook observed? It does not establish whether a claim is true in the outside world, or
whether the recorded tool output was honestly produced. Those boundaries are deliberate and are
also stated in the [project README](../README.md#what-it-does-not-do).

## The rule

A claim is only as strong as the evidence the session retained for it. Makoto therefore keeps the
agent's own pending tool calls, completed tool events, and closing message separate from the
user's words. The dispatch path is implemented in
[`makoto/_dispatch.py`](../makoto/_dispatch.py); session claims are extracted in
[`makoto/session/commitments.py`](../makoto/session/commitments.py) and retained evidence is read
through [`makoto/record/ledger.py`](../makoto/record/ledger.py).

The rule is not a claim of omniscience:

- A record of a runner invocation does not authenticate the runner's output.
- A citation can be checked against Makoto's local allowlist, not against the world's literature.
- A file touch can support a location claim, not prove that the file fulfils every intended
  semantic requirement.
- A safety or access-control decision belongs to another control; it is not evidence that the
  agent's statement was kept.

The local citation allowlist is [CITATIONS.md](../makoto/docs/CITATIONS.md). Its consumer is
[`phantomCitation.py`](../makoto/checks/phantomCitation.py), which limits enforcement to the
project tree governed by that allowlist.

## Where the rule is enforced

The live catalog is discovered by
[`makoto/substrate/_loader.py`](../makoto/substrate/_loader.py), not copied into this document.
The user-facing catalog and its exact counts are generated by:

```console
python3 -m makoto pattern list
python3 -m makoto pattern show gate.relative_path_citation
```

The two central kinds of evidence are:

- Pre-tool predicates inspect the content that an agent is about to write. Their common helpers
  are in [`makoto/substrate/factories.py`](../makoto/substrate/factories.py).
- Stop checks compare the agent's closing claim with session and filesystem evidence through
  [`makoto/_dispatch.py`](../makoto/_dispatch.py) and the modules in
  [`makoto/checks/`](../makoto/checks/).

For example, [`claimedProduceAbsent.py`](../makoto/checks/claimedProduceAbsent.py) handles a
specific “I produced this file” claim, and
[`falseGreenClaim.py`](../makoto/checks/falseGreenClaim.py) compares a green claim with recorded
test-run evidence. A complete check inventory is intentionally a loader result, not a prose list
that could drift.

## Honest failure modes

An input that is absent, empty, malformed, not a JSON object, or names an unknown hook event is
**NOT_EVALUABLE** and is refused with exit 2. That avoids turning a missing event into a green
evaluation. Once a complete envelope is present, operational failures such as a transient database
lock remain loud and auditable but do not invent a finding. The distinction is tested through the
actual entry points in
[`tests/test_entrypoint_input_validation.py`](../tests/test_entrypoint_input_validation.py).

The self-wiring guard has one deliberate blind spot: a single edit that removes all hook entries
can disable the guard at the instant it would report the removal. The current evidence, scope, and
non-claim are maintained in the [self-wiring follow-up](self-defense-asymmetry-followup.md).

## What this document is not

This is a current implementation guide. It does not cite removed directories, unshipped design
notes, or sibling repositories as if they were live evidence. Historical removals belong in
[`CHANGELOG.md`](../CHANGELOG.md); current source claims in this document are local links and are
checked by [`makoto.reference_integrity`](../makoto/reference_integrity.py).
